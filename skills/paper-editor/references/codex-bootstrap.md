# web论文写作：Codex 材料入口

本入口为本地 Codex 会话提供材料准备与交接流程。材料包括科研主线、方法实现、实验设置、可核结果、图表原始数据与可编辑图源、Zotero/BibTeX 和来源索引。Chat 端随包的反防御写作规则用于 [Chat 写作入口](chat-writing.md#普通-chat-的项目与写作风格)中的正文写作及返修。Codex 继续按材料交接任务整理证据。

先读当前工程 AGENTS、PROJECT_MEMORY、已有 PROJECT/HANDOFF/STATE/路径映射，以及实际来源与冻结协议。材料解释依据当前项目规则、材料入口和任务范围，不因材料缺项启动训练、采集、调参、Bootstrap 或测速。

## 确定唯一写作根

新工程默认实体 `<已核实工程根>/PaperWriting/`。根必须来自本轮实际宿主与工程事实；同名代码库或另一篇论文不能共用项目身份。既有权威写作根可原位映射，避免仅为命名统一复制第二套主稿。若用户已经明确指定工程下实体 PaperWriting 并要求归集，按该授权执行，不重复询问，也不让原位映射偏好阻断它。

归集前核对最新源稿、来源/输入哈希、接受记录和全部依赖；不以目录编号或修改时间选择新版。授权内归集当前稿、图源/可编辑原件/生成器/真实小型数据、冻结结果摘要、成本与实现说明、批注/响应矩阵、BibTeX及构建支持。原始大数据、权重和run目录保持外部引用；本地参考文献默认保留 Zotero/来源索引与必要 BibTeX 快照，全文按 [文献](zotero.md) 与 [Drive](drive-sync.md) 处理。

逐文件记录来源、目标、SHA和可访问状态。保留旧材料及回滚依据，明确新根为唯一后续写作入口，旧根标历史；不删除历史或默默恢复旧根可写。只读/未授权旧入口用新根映射说明，不强改保护。核实际 includegraphics、书目、图源数据和 input_manifest；脚本中的旧绝对路径/默认输出需单列待适配，不能直接运行。旧PDF标真实版本，不能冒充当前稿交付。

接续图件时，按 [Chat 写作入口](chat-writing.md) 中的两条制作路线与作者选择处理。修改已有图和 Windows 接续默认本地制作；参考图复刻可由云端制作，再用项目 Drive 的原格式 PPTX 桥接回收。工程交接完成前核对本地原件身份，缺少素材或接收入口时只询问必要的一项。同步核对当前已采纳图源和待审候选。发现图源仅在 Drive 或 Chat 临时环境时，按作者指定的文件 ID 和项目候选路径回收可编辑原件及必要输入，先核 Drive MIME、大小和可用校验和，再以本地实际字节计算 SHA 并读回确认。已转换为 Google Slides 的文件按实际导出类型登记来源。恢复后的工作文件留在同一 `PaperWriting`，后续 PDF/PNG 从该本地源生成并完成实际视觉检查。候选与既有已确认论文修订分别登记，采纳依作者确认执行。交接给 Chat 的记录包含准确路径、图号、语言、源 SHA、预览与构建状态，以及已有 Drive ID，使用已启用的索引或这些明确路径定向读取。


新项目配置构建服务时，将实体工件根放在唯一PaperWriting的受保护 `builds/` 子树，并核实际注册、路径隔离和普通编辑保护。历史外部工件的实体归集是独立的获准迁移；按[工件存储规则](workspace-layout.md#构建工件的项目内存储)保留SHA、任务ID、历史原文及回滚依据。初始化脚本建出的空builds目录不等于工件已归集，不自动触发历史搬迁或全量Drive上传。

## 初始化脚本的真实能力

直接使用项目已有的官方模板与来源清单。选择共享规范库时，按[双库协作](dual-library.md)核对规范版本和成员哈希。`paper-bootstrap` 提供通用的项目骨架与材料索引初始化；已有论文沿唯一稿根接入。外部规范库的初始化器仅在实际存在、适配当前项目且获准时使用。

在管理工程先核 CLI `--help`，使用已配置工具链，例如：

```bash
paper-bootstrap --project-root /absolute/research-project --paper-root /absolute/research-project/PaperWriting --project-id verified-project-slug
```

旧权威目录可显式传 `--paper-root`；`--manuscript-dir` 是实际论文相对目录，重复 `--source` 是原工程索引范围，`--tunnel-registry` 是实际清单。当前脚本会优先选择已有 PaperWrite，两种根并存时报错，故用户已选新根时必须显式传入，不能依赖默认推断。

**脚本只建目录、契约骨架、字节哈希与索引，不复制 source，不生成科研内容简介、README 或 Chat 提示词，不注册服务、不上传全文、不构建论文。** `--source` 不是归集完成证据。当前实现复用已有契约，不能用它迁移已有根或推断论文版本；保留手改与科研事实，再由 Codex 在授权内补真实材料、路径映射和交接。`--gateway-config` 仅在实际支持时做项目范围的只读 Zotero 索引，不代表全文已同步。

## 补齐材料与接续条件

实际阅读后归纳研究问题/科研主线、输入输出/方法、数据与评价设置、主要/负面结果及限制，逐项关联材料入口。冻结预测、保存的置信区间和统计口径不重算或偷换。新项目尚无结果时写“尚无”，不为填表制造实验。模板契约和空目录不能当完成。

按 [项目契约](project-contract.md) 维护 PROJECT/HANDOFF/STATE/映射、材料/文献/图源索引；按 [Codex 交付](codex-delivery.md) 补 README、完成说明和 `CHAT_POLISH_PROMPT.md`。有等价文件就映射维护，不能另造竞争事实源。

按 [工程结构](workspace-layout.md) 明确稳定规则、身份声明、动态状态、科研简介与接续步骤的各自责任。四类索引复用实际文件，以角色/字段映射区分文件归集、主张支持、构建输入与图件来源；历史布局可兼容，不为了规范搬目录。初始化脚本仍只产通用骨架，四类角色和分层完成度需Codex核实际证据后补齐。

初始化、服务注册、Tunnel连接、Drive同步是独立状态。按 [Tunnel](tunnel-management.md) 核验实际清单/授权，已有明确绑定或共享凭据修复授权可执行；没有授权时列具体缺口，继续独立本地整理。新根还须核 Native登记、Runner根、OS权限、Gateway白名单、构建输入/输出身份；只改PROJECT不等于服务可用。

按 [Drive](drive-sync.md) 核实用户指定的语义项目名称、完整云路径、folder ID与parent；不默认以代码库名称作为论文名称。用户要求全文归档且已授权时完成真实PDF上传、缺项处理与读回，不能交一个索引便声称全文齐全。连接或云端局部失败不抹去本地已完成项。

完成前必须执行 [Codex交付清单](codex-delivery.md)，向用户报告所有栏目及推荐Chat提示词，不只留下“待整理/待注册”的空建议。
