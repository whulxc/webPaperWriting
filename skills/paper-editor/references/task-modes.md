# 任务模式与成果粒度

按本轮用户实际意图选择最小充分工作范围；不要把单段润色升级成重写整个工程。

## TARGET_READ（已知版本、语言、角色或图号的只读取件）

- 已有可信项目绑定时，按 [精确目标取件](indexed-targets.md)直读；不为单件请求盘点runtime/工程、搜索Drive或进入FIGURE_EDIT。
- **必交**：请求的实际内容或已核文件链接及必要的版本/修订、语言、图号与SHA身份。未启用、缺项或失效如实说明；不擅自构建、发布或套完整材料交接清单。

## FULL_PAPER（全稿创建、全面润色/重构）

- 根据当前项目材料、事实登记和目标期刊规范设计完整论文结构；如已有源码则基于最近已核验候选继续。
- 必要的章节、公式、表格、引用和图件都要有可编辑源。将候选 TeX 交本地受控构建器；检查引用、PDF 页数和视觉布局；需要时按实际检查反馈修订。
- **必交**：完整且可打开的 PDF（优先 Drive 实际文件链接，可能再附正文页面预览）、构建版本/ID、主要修改、实际检查覆盖与未通过项。无完整 PDF 时说明未完成这一交付环节。

## SECTION_EDIT（段落、章节、公式、表格）

- 定位准确的 source section 和所引用的事实或图件，保留非目标章节。执行候选 TeX 修改，验证交叉引用和必要构建。
- **必交**：供用户确认的完整目标段落/章节（用户可在 Chat 中阅读或复制）、具体改动；若用户要求或版式变动较大，再额外交付相应页预览或 PDF。
- 长章节时可以以可读文本文件和摘要交付，明确文件真实存在并可访问；不能把未执行的 diff 当作已写入。

## FIGURE_EDIT（单图、流程图、模型结构图、数据图）

- 选择真正可编辑源：统计图 Python/MATLAB+数据；方法示意 PPTX/SVG/TikZ；复杂图按论文实际需求选择。保留对象、标签、图层或脚本、数据哈希。
- PPTX 按 [Chat 写作入口](chat-writing.md) 的两条路线选择。修改已有图或接续 Windows 编辑时默认本地创建/编辑，任务完成后用 `paper_build_artifact(action="copy_to_candidate")` 回写实际工件。参考图复刻且云端能力更合适时可云端制作，先用项目 Drive 桥接原始 PPTX，再按文件 ID 回收获准候选路径。用户指定路线优先，只有实质取舍或缺少所需素材/入口时才询问。两条路线均核本地 SHA 与对象信息，多页合成版和单页版登记到同一候选批次，作者采纳后更新论文修订。
- **必交**：本轮实际已渲染图件的项目 Drive 审阅链接、可编辑源在 PaperWriting 的位置、用于稿件的导出文件身份和主要改动。Chat 需查看图件、PPTX 或页预览时，通过相应 Drive ID 读取。原生对象可编辑性按实际检查结果记录。
- 若只改一张图，不要求无意义地在聊天里输出整篇 PDF，但应检查插图尺寸及必要的 TeX 依赖。

## REFERENCE_EDIT

核对 Citation Key、条目元数据、文内引用、目标期刊参考文献风格；报告不能查证的条目。不得虚构 DOI、作者、页码或出版状态。交付实际变更的 `.bib` / TeX 引用片段。启用受管版本的项目在 draft 版本内 `stage` → 编辑 `working/deps/` 副本 → `dependency` → `revise`，见[受管版本](managed-versions.md#文献与支持文件依赖候选)。

## PDF_REVIEW

- Runner 可在本机解析、渲染和检查 PDF。Chat 需要看页面时经项目已核 Drive PDF 或页预览 ID 读取，再检查字体、浮动体、留白、公式断行、表格溢出、图例、裁切和页码，记录实际看过的页。
- 给出页码、图号、问题等级、对应 TeX/图源、可执行修复动作。用户若要求修正则进入新的候选版本。

## VERSION_COMPARE

已有两份 TeX 且只需审阅文字改动时，按[轻量文字对照](review-confirmation.md)生成一份红色删除线、蓝色下划线的标记 TeX 和审阅 PDF，沿用原模板和当前稿号。正式版本对比基于真实文件哈希、TeX diff、图件源及 PDF 页面差异；不得从版本号猜测内容。保存工作修订按本轮明确要求执行。

## ANNOTATED_PDF_REVISION

详见 [批注 PDF 返修](annotated-pdf.md)。先交批注处理对照及本轮要求的审阅件，作者确认后按本轮要求保存修订，不能静默跳过看不懂的标记。

## REVISION（全文修订）

适用于已有完整 TeX、PDF、图件、实验结果和引用，且需要重构科学主线、章节顺序、图表序列或贡献表述的任务。

1. 先核验父稿、当前源、版本和作者锁定内容。
2. 按 full-workflow.md 执行 RESEARCH_PREFLIGHT 和 EVIDENCE_AUDIT。
3. 生成或更新 WRITING_BRIEF.md，先交修订蓝图和证据缺口。
4. 依据本包的 Brief 和编辑规则完成结构与图件设计，外部技能可按需辅助，作者确认重大科学取舍后再写入。
5. 由 webPaperWriting 和所选项目连接执行受控 TeX 修改、构建、审阅和 Drive 交付。
6. 保留旧版本和真实差异。未授权的正式版本晋级不自动执行。

## REBUILD（原始材料重构）

适用于科研工程中有实验、结果、图源和文献，但旧稿结构不再作为可信写作基线的任务。

1. 只从 PaperWriting 索引和真实来源提取科研事实，不把历史草稿当真值。
2. 完成 RESEARCH_PREFLIGHT，默认记录三篇分别用于科学主线、实验叙事和图件设计的参考论文。
3. 依据 Brief 设计论文、章节、图件、段落和关键句的蓝图。
4. 依据本包图件要求设计可编辑科学图件，定量图关联真实数据或冻结结果。
5. 建立独立论文身份时不替换其他论文的正式版本。
6. 构建、审阅、Drive 交付和版本回执均按真实工具和授权执行。

REVISION 和 REBUILD 都必须在写作前标出已验证结果、作者决定、历史草稿和待验证主张。它们是完整流程标签，不改变现有 SECTION_EDIT、FIGURE_EDIT、REFERENCE_EDIT、PDF_REVIEW 和 ANNOTATED_PDF_REVISION 的快速入口。
