# Chat 文件交付策略

本文件决定文件如何进入 Chat，优先于本技能其他参考里的附件、分片、资源链接和预览动作说明。先读取所选项目 `paper_capabilities` 顶层的 `chat_file_delivery`。同一会话沿用该连接已核设置，换绑或配置变化后重新读取。实际连接返回 `drive_links_only` 时采用下面的链接模式。连接返回其他已支持值或旧独立安装未提供该选项时沿用兼容模式。仅更新技能文件不会替项目启用连接设置。

## drive_links_only

论文 PDF、图件、PPTX、页预览及其他需在 Chat 展示的本地文件经本项目 Drive 传递。先复用身份匹配的已核文件 ID；需要上传时只使用当前项目实际支持且已授权的原 Publisher 或单文件入口。核文件类型、大小、SHA 和父目录后，给用户真实 Drive 直达链接。Chat 需要读文件时由 Drive 连接器按该 ID 读取，按实际可读结果说明已查看的内容或页面。

用户明确说“给附件”“下载到聊天”或“直接显示图片”时，也采用上述 Drive 方式。有可用链接就交付链接；文件只在本地或 Drive 当前不可用时，说明本机已保存的位置和缺少的可用链接，并继续本轮已授权的修复。保留已有本地产物和来源回执，不邀请“允许一次”、切换附件、分片下载或其他传输豁免。日常附件请求不改变连接的交付设置。

Chat 不通过项目连接调用会直接返回图像、原始文件或宿主资源的 `image`、工件 `export`、二进制 `chunk`/`content`、ResourceLink/resource、预览 widget 或章节下载入口，也不创建聊天附件与下载按钮。旧帮助文本列出这些动作时，只表示历史能力存在。服务按当前连接设置约束出口，技能按同一设置选路。

项目连接与本地 Codex 可继续读取/编辑源文字、查询文本和元数据、在本机执行构建/渲染/检查、用 `copy_to_candidate` 保存项目内工件。`paper_pptx_edit(action="export")` 仍可作为本地渲染作业；Chat 展示其输出时采用 Drive 路径。云端制作 PPTX 先上传项目 Drive、再按文件 ID 回收本地候选的两路线流程继续有效。展示沿用实际稿号，正式论文发布按作者指令执行。

这个模式通过选择链接交付减少本地文件进入宿主的操作。宿主自身的批准要求仍由宿主执行；技能和 MCP 不能承诺豁免平台审批。由 Drive 连接器读取文件时，按该连接器实际授权和读取结果处理。

## PDF 审阅与正式发布取件

用户要求看指定稿件时，先按项目、完整版本路径、修订、语言和主 PDF 哈希定向取现有审阅或发布回执。已有文件 ID 时，按该 ID 核对 Drive 元数据并复用链接。需要交付当前成功构建时，使用 `paper_publish_to_drive(review_pdf={build_id,sha256,language,project_folder_id,parent_id})`；该入口支持受控净稿和标记稿。核对回执中的构建 ID、语言及 PDF 身份。对于同一构建、名称和目录，使用原参数可取回原审阅回执与链接。源文件已变化时按已有回执读取先前审阅文件，或按本轮授权重建当前稿。

当前受管稿件使用 `paper_version_derive(action="status",version=<父稿>,revision="rev-NNN")` 按索引取 `review_deliveries`。该取件查询须显式传入修订；只传父稿的普通 status 仍用于读取管理状态。结果中的 `remote_revalidated=false` 表示返回本地已核回执；给出链接前用 `paper_drive_verify` 按返回的文件 ID、SHA、大小和父目录实时核验。`review_deliveries.items[]` 内的 `current_inputs_verified` 说明各成品是否仍匹配当前源，所选历史审阅文件沿其原修订身份说明。索引缺项时报告缺项，保留已有准确回执，按同一构建和原参数调用 `review_pdf` 可幂等补登记。

正式发布时，已提升的修订也可用 `paper_publish_to_drive(version="<父稿>@rev-NNN")` 精确选择。`FORMAL_ARCHIVE_REQUIRED` 的 `discover` 给出父稿与修订的状态查询，`review` 给出单文件审阅入口，`formal` 给出获准正式提升所需的参数与证据。`VERSION_SELECTION_REQUIRED` 提示先选择父稿。沿错误返回的实际身份继续处理，并核对所选语言和稿件。

`rev-NNN` 是受管论文中的工作修订号。正式发布参数 `version` 使用现存不可变归档的真实标签；通过所选论文的版本状态与正式提升记录核实它对应的修订。用户明确要求正式发布时，按当前入口完成所需归档和发布，使用工具实际返回的标签。父稿路径、工作修订、构建 ID 和正式归档标签各自沿用真实记录，缺少映射时按完整父稿和修订定向查证。

收到 `Version not found` 或正式发布错误后，核实该次调用的参数和归档状态，同时检查所选稿件的审阅回执。审阅交付与正式归档分别按真实回执报告，已有匹配审阅链接时仍应提供。只有已核实的对应文件 ID、大小、SHA 和项目目录可作为交付依据；缺项时说明具体缺项并继续本轮已授权的修复。查询沿既有索引和准确 ID 进行。

## 兼容模式

当前连接未返回 `drive_links_only` 时，采用用户选择且实际可用的渠道。已配置 Drive 时可复用已核链接。纯本地工作交付真实文件位置；需要客户端接收文件时，按工具 Schema、用户要求和宿主批准流程交付最小范围，核完整字节与 SHA。客户端不支持该传输时保留本地产物并记录具体缺口。
