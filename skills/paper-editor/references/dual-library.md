# 可选规范库与项目版本锁

项目可以直接使用本地已核规范，也可接入用户自己的共享规范库。每篇论文的 PaperWriting 保留唯一主稿。技能版本、软件发行版、规范库版本、工作修订、构建和正式论文版本分别记录。

## 本地规范

先记录目标期刊、文章类型、官方规范来源、取得日期、模板及其 SHA256。需要跨会话复用时，在项目 Brief 或既有配置中引用这些文件。规范变更先比较受影响章节、模板和图件，再按作者目标采用。目录显示名和文件时间不能代替内容核验。

## 用户选择云规范库时

用户提供实际入口与权限。按真实文件或目录 ID、清单、相对路径和 SHA 定位规范，记录所选 release。可用 `ACTIVE_LIBRARY.json` 指示共享默认版本，字段含 `library_version`、`release_id`、`manifest_file_id` 和 `manifest_sha256`，实际格式以该库契约为准。项目保留自己的版本锁，新增默认版本后先提示差异。

读取所选任务需要的规范，保留来源和取得范围。Drive、Zotero 或其他连接的访问权各自授权。当前安装未提供规范库管理工具时，使用用户已有的库维护流程或保存本地可审查候选。写作工具的项目权限只覆盖登记的论文工作区。

## 发布、镜像与回流

规范维护源生成候选，获准发布时固定清单和成员哈希。只读镜像按已核清单取得，历史 release 保留原身份。切换正式入口需明确授权、刚读到的前驱身份和条件更新。响应丢失时先核实际对象和状态，再决定是否重试。

| 状态 | 处理 |
| --- | --- |
| `matched` | 内容一致，复用对应对象和 ID |
| `local_only` | 在获准范围内增量交付 |
| `remote_only` | 先核角色，审阅材料导入新候选 |
| `diverged` | 保留双方来源和内容，交作者解决冲突 |
| `excluded` | 原始数据、权重、缓存、凭据及无分发权全文仅记来源 |

没有共同基线时记录未知。审阅意见通过实际可用的 `paper_source_sync(action="import_review")` 或等价的用户工具导入获准候选区，记录文件 ID、父目录、SHA、稿件基线和 request_id。内容冲突保持可见，冻结结果和论文主稿按原授权处理。

大文件经项目选定的交付渠道传输。MCP 的响应上限按当前 Schema 和宿主设置执行。记录本地文件、构建、远端校验、客户端接收、实际审阅页码及作者接受的独立状态。项目文件交付的选路见[文件交付策略](file-delivery-policy.md)。
