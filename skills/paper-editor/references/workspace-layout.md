# 写作工程结构、文件职责与四类索引

## 必需契约与推荐目录

规范约束信息职责、唯一权威来源和可验证依赖，不要求历史工程长成同一棵物理目录树。新项目可用 manuscript/materials/figures/references/reviews/builds/sync；已有目录通过 PROJECT 的 logical_paths 和路径映射接入。缺少同名 figures/、methods/ 或 experiments/ 不自动判不合规，必须检查等价角色实际有无材料与入口。不得为了通过形式检查创建空目录、复制第二份权威材料或擅自迁移依赖。

## 构建工件的项目内存储

新项目默认把实体构建工件保存在唯一 PaperWriting 下的受保护 `builds/` 子树。项目契约和实际服务配置须明确工件存储根及其子目录布局；构建任务、持续编辑稿和不可变审阅版本分别保留身份，不能把 `artifact_root`、`rb_...`、`bNNN` 或论文版本号混用。复用既有构建器的目录规则，不为目录外观重写已验证引擎。

每次构建保留当时源码/依赖快照、请求参数、PDF、日志、页图、manifest及SHA256和可恢复来源。大型原始数据、权重和科研run继续按显式外部来源与hash关联，不因工件归入项目而复制进来。普通文件编辑工具不能修改或删除历史 `builds/`；仅构建管理机制按项目授权创建独立记录。工件默认不加入Git，也不因位于PaperWriting就全量纳入源码同步；Drive交付使用明确选择的快照与发布清单。

历史外部工件布局可显式兼容，必须提供真实路径及项目内可定位入口。用户已授权实体归入PaperWriting时，先核对活动任务、现有依赖/链接、容量、逐文件SHA及回滚路径，再迁移和切换实际服务配置；保留原任务ID、版本、已发布Drive身份和旧终态。历史manifest、日志中的绝对路径作为来源证据保持原字节，当前执行/读取位置另用经核验的路径映射表达，不能机械替换历史内容或复制第二份可编辑主稿。迁移后实际验证旧任务查询、PDF/页图读取、新工件输出、普通编辑拒绝和发布恢复，不以目录存在或软链接可读代替完成。

## 各文件的唯一职责

| 文件/角色 | 负责什么 | 不承担什么 |
|---|---|---|
| AGENTS.md | 稳定规则、授权边界、读取顺序和权威来源指针 | 不反复硬写“未注册/已上线/上传N份”等易变状态 |
| PROJECT.yaml | 项目身份、唯一稿根、当前稿路径/版本声明、逻辑路径、Drive名称/ID、声明的scope及状态入口 | 声明不证明实际服务权限；动态检查结果引用STATE |
| PROJECT_STATE.json | 带观测日期和证据引用的连接、交付、未决项和分层完成度 | 不改写科研原始结果，不把上一轮报告当本轮实测 |
| README.md | 面向人的导航与科研主线/方法/设置/结果简介，给出证据入口和范围 | 不是新的数值权威表或独立连接状态账本 |
| HANDOFF.md | 接续顺序、当前任务边界、未决事项入口和下一步的条件 | 不复制另一套状态列表，建议不等于授权 |
| CHAT_POLISH_PROMPT.md | 面向后续Chat的已填任务、发现/必读/写入边界和交付要求 | 不自动在本轮执行提示词中的未来编辑任务 |
| 路径映射 | 逻辑角色到现有物理位置、原路径到现路径、兼容别名 | 不存另一套实时连接/构建状态 |
| reviews/验收回执 | 某次检查的范围、日期、输入身份、结果和限制 | 历史回执保持历史，不能覆盖成最新状态 |

新规范兼容旧契约；旧字段有消费者时，先核依赖，再保留标明语义的兼容别名或状态引用。不要突然删除下游必需字段或改变类型。实际服务scope仍以live核验为准，不能通过修改契约获得权限。

## 四类索引，四种证明范围

优先复用已有等价文件，用轻量索引目录元数据（如 materials/INDEX_CATALOG.json）登记 role/path/format/schema、字段映射、更新责任、覆盖范围与兼容别名；该目录元数据不是第五套科研事实索引。不因旧文件名字叫 evidence 就自动把它当主张证据表。

| 角色 | 最少信息或已有格式的等价映射 | 证明范围 |
|---|---|---|
| file_inventory 文件来源清单 | source、destination、SHA256、大小、来源/快照时点 | 文件从哪里来、复制是否一致；不证明科学结论。一次归集清单不自动包含之后所有新增文件 |
| claim_evidence 主张证据表 | claim_id/主张、source/path、SHA256、selector、统计单位/分母、稿件位置、验证状态；代码/数据版本或来源协议引用，不明记缺口 | 指定主张与证据之间的关系；部分关键主张覆盖不能称全文逐句支持已核 |
| build_inputs 当前构建输入清单 | 当前稿/图/书目/模板等精确输入路径和SHA，关联构建交接中的引擎、依赖、cwd、独立输出约定 | 当前输入身份；仅包含必要文件的清单不证明环境完整或编译成功 |
| figure_index 当前图件索引 | 当前图号/label、旧图号映射、实际渲染件、可编辑图源/生成器、数据和input_manifest、存在/SHA/生成与视觉状态 | 当前图与来源的关联；文件在场不证明生成器已适配新根或图已重绘验收 |

文献索引及云同步账本独立保留，不冒充上述任一类。角色路径可以不同于推荐文件名，但必须明确可定位。目录内优先相对路径；外部来源使用显式根/绝对引用并标注可访问状态。为追溯保留的历史绝对路径不得机械全局替换；当前执行路径另用映射/交接明确。

## 分层完成度与核验

分别记录：材料已收纳、可接续写作、可重新构建、视觉验收。各层有自身证据及限制，不以一个总布尔值代替；上层未完成不抹去已经完成的本地材料工作。文字接续就绪不代表图源已可执行，输入哈希通过不代表编译通过，抽查不代表逐页验收。

维护后检查：JSON/YAML/CSV可读；权威文件职责和引用无互相矛盾；逻辑角色/别名均解析到真实材料；四类索引字段映射、覆盖口径和来源SHA一致；当前TeX图/书目依赖可定位；保护稿件/图源/冻结证据与维护前哈希相同。检查范围与本轮修改相称，不为结构核验编译、执行生成器或新增实验。完整回执保存本轮结果，STATE指向它，历史回执不重写。
