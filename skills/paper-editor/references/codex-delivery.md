# Codex 完成情况与交付清单

适用于 Codex 端的初始化、归集、接续核对和连接/交接维护。结束时向用户提供下面六项简明说明，可用表格或短段落；不能仅给 README 链接代替。可复用本会话已核且未变化的证据；本轮未读、未完成或不适用要明确写出，不为填栏目运行新实验。详尽清单留工程，用户应从回复大致看懂整理了什么、能否开始写作。

## 六项必报

1. **工程与 PaperWriting**：真实宿主、工程绝对根、唯一写作根及可点击入口；实体归集还是原位映射；当前源稿/语言/版本、历史PDF、主要材料入口与仍缺依赖。不得把旧原稿README当最新状态。
2. **论文材料基本情况**：
   - 科研主线：研究问题、任务、核心论证与适用边界。
   - 实验方法：输入/模态、关键模型或算法、融合/决策机制及主要对照/消融；区分冻结主方法和探索候选。
   - 实验设置：数据量与统计单位、样本/窗口关系、数据资格/缺失值、划分与防泄漏、seed的真实含义、平台/成本口径。
   - 实验结果：真实主指标及不确定性含义、关键对照/消融和局限；关联表/报告入口。不隐藏混合或负面结果，不把桌面测量写成设备实测，不用初始化标准差替代簇置信区间。
   每项来自实际读取的证据。材料只提供计划/代码时写“计划/已实现，结果未核”，不虚构结论。无需长篇复述，但不能只有“材料已整理”。
3. **参考文献库**：分别报告当前稿唯一引用键数、Bib条目数（若不同）、Zotero匹配/冲突/缺失数，以及已验证完整全文数、Drive上传并读回数和缺项。给出本地索引/Bib位置、实际Zotero库或集合（未确定写未知）、Drive Fulltext路径及链接。数量分母与去重口径明确；书目身份、完整PDF、已读全文、句级支持是四种状态。
4. **Tunnel/MCP**：连接显示名/alias/实际Tunnel ID、Runner、服务实际项目ID与根、当前可读/可写范围；分别说明登记、健康、成功云轮询/实际请求、本地读写探针、Chat独立发现的状态。密钥仅报告“本机安全引用/是否复用与已验证”，不输出任何值/片段；共享凭据不合并项目身份。旧构建配方是否仍匹配当前输入必须说明。
5. **Drive双库与项目**：公共规范ACTIVE和正式manifest身份、项目规范锁与已核本地镜像；用户认可的项目显示名称、完整逻辑路径、实际folder ID与链接、已同步范围（全文/源稿/图件/版本）和未同步项。首次对齐报告matched/local_only/remote_only/diverged/excluded，云端Reviews回流另计。更名须按已核ID原位完成、读回名称和parents，并同步身份说明/注册表/本地映射。代码仓库名、论文名称、技术ID分别处理；不能误用同名的另一篇论文。只有实际读取公共规范/镜像时才报告其通过，未配置或本轮不涉及明确写出。 本地同步说明分别列规范维护源、冻结release候选、SHA verified只读镜像、Drive Desktop流式/离线目录、项目PaperWriting和各宿主Skill的真实路径与范围；Skill分发独立于Drive同步，不把可见目录称为完整备份。
6. **Chat接续**：提供“web论文写作”的可直接发送推荐提示词正文或清楚的可复制文件链接，并概述该提示词的实际任务。为专用普通 Chat 指定一个目标 App/Tunnel 和预期真实 `project_id`，说明首次核对后可省略重复 `@` 和 ID；Chat 的每回合写作风格调用按其专属入口执行。必须包含选哪个连接、发现哪一根、先读哪些文件、允许修改哪些内容、科研不变量、未验收项、写后核对与交付要求。采用 [Chat模板](chat-handoff-template.md) 填当前证据，不残留占位符、不猜工具。

## 工程内交付

在唯一写作根复用或维护 `README.md`、`HANDOFF.md`、`PROJECT_STATE.json`、契约/映射和 `CHAT_POLISH_PROMPT.md`。README/HANDOFF给出上述材料简介和真实来源入口；状态、引用计数和当前版本有单一权威来源，其他文件引用它或保持一致，不各自发明数字。材料数量/大小统计不代替研究内容说明。

具体职责和四类索引遵循 [工程结构](workspace-layout.md)：README承载科研简介，HANDOFF引用该简介并给接续步骤；动态连接/构建/交付状态归STATE，AGENTS保留稳定边界。交付前核对入口一致性，明确材料收纳、写作接续、重新构建和视觉验收四层，而非只报告目录存在。

最终明确分开：材料读取与归集、静态检查、服务注册、真实写入、编译成功、逐页视觉审阅、Drive上传读回、Chat字节/预览接收及用户打开。默认向 Chat 交付核验过的项目 Drive 文件 ID 和直达链接。Chat 所需的论文 PDF、图件、PPTX 与页预览均经该 Drive 路径，附件请求按[文件交付策略](file-delivery-policy.md)处理；未要求独立完整字节校验时明确该项不在本轮范围。未完成的项有具体原因和下一步；不把本机自测写成Chat已验收，也不因存在历史PDF宣称当前稿已完成。

## 简明回复骨架

```text
已完成：<本轮实际完成范围>；尚未完成：<具体项和原因>。
PaperWriting：<绝对路径与入口>；当前源稿<版本>，PDF/视觉状态<真实状态>。
材料简介：科研主线<…>；方法<…>；设置<…>；结果<指标/不确定性/限制及来源>。
文献：引用<N>，Zotero匹配<M>/冲突<C>/缺失<K>；完整全文<P>/<分母>，Drive验证<U>/<分母>；位置<索引、Zotero、Drive>。
连接：<名称/ID/Runner/实际项目/root/写scope>；登记/云连接/Chat验收<分别说明>。
Drive：<语义名称、完整路径、已核链接>；同步范围<…>。
发给Chat：<已填好的提示词或可复制文件链接>；先<发现和必读>，执行<授权任务>，交付<结果>。
```

## 全文任务的额外交接

当任务模式为 REVISION 或 REBUILD 时，Codex 交付必须额外提供或引用：

- WRITING_BRIEF.md 的真实路径和当前状态
- RESEARCH_PREFLIGHT 的真实路径、三篇参考论文的 DOI、阅读范围和证据等级
- Evidence Audit 和 Claim–Evidence Ledger 的真实索引
- Figure Storyboard、图源路径、数据来源和图件哈希
- 目标期刊和稿件类型
- 本包内置反防御写作规则及实际可用的可选写作、图件技能
- 所选项目连接的实际 project_id、构建入口、允许写入范围和 Drive 交付方式
- 需要作者确认的科学取舍和未验证内容

这些字段用于跨宿主写作，不复制原始数据或全文文件，也不替代项目状态和版本回执。
