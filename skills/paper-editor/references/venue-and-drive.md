# Drive 当前规范调用契约

本文中的 Drive 路线适用于已配置且选择该渠道的项目。无 Drive 的项目可继续本地工作，并按[文件交付策略](file-delivery-policy.md)使用实际可用且获准的 MCP 文件接收。`drive_links_only` 只在连接明确返回该设置时生效。

本文件说明如何按已发布身份读取公共规范，不复制整库，也不以 Skill 概括替代真实文件。公共规范版本、Skill版本、工具发布版本和论文版本分别锁定。

## ACTIVE 入口与首次读取

先从当前项目契约、已核本机登记或用户提供的真实根Folder ID定位 `ACTIVE_LIBRARY.json`，核其ID和parent。读取其中实际 `library_version`、`release_id`、正式规范folder、`manifest_file_id`、`manifest_sha256`、入口路由、发布时间和发布状态；再取manifest核字节SHA。规范库与写作项目库是并列角色，不把论文项目目录、旧项目档案或同名目录当成公共规范入口。具体流程见 [双库协作](dual-library.md)。

从manifest按相对路径、Drive File ID、parent和SHA定位真实Markdown原件，再按入口路由选当前唯一任务行，起步读取2–3份相关文件和章节。当前连接支持 `text/markdown` 时直接读 `.md`；不默认检索 `_TXT_MIRROR/` 重复副本，不用ZIP作为唯一交付，不仅按文件名搜索。旧固定公共链接集中在 [历史链接](historical-drive-links.md)，仅显式追溯时读取，不能回退为当前默认。

新项目采用实际已发布且核验的规范锁；既有项目继续其已记录版本。若ACTIVE比项目锁新，显示差异并按明确任务更新，不能静默切换。项目没有锁定记录时先报告缺口，在实际可写契约或映射中登记候选采用范围；不能为登记版本扩大权限。已确认未变化的规范可在同一会话复用。

2–3份是起步预算，不是证据硬上限。实际稿件、数据和必要协议优先；发现事实、适用期刊/文章类型/阶段、版本或来源冲突时按具体缺口补读。身份不明时核当前项目，不因名字相似合并不同论文。先完成当前小步并交真实产物与状态，避免阅读长清单代替制作。

## 详细任务索引：只扩展当前路线

先执行当前锁定release路由的最小读取。本表仅在当前小步需要对应规范、项目覆盖或案例时定位材料，**不要求把同一行列出的文件全部追加读取**，也不覆盖快速路由的章节级替换规则。已读来源复用；补读只为解决当前证据或执行缺口。

| 当前任务 | 按需规范与案例选择（非全读要求） | 本轮执行检查 |
| --- | --- | --- |
| 全文写作/全面润色 | 期刊规则、通用写作规范、章节任务卡、证据契约、本项目 WRITING_PROFILE；按引言/方法/实验/讨论问题查章节案例 | 论点与证据逐项对应，章节承担不同论证作用，事实和评价单位不变 |
| 单章/段落修改 | 入口、章节任务卡中对应章节和本项目术语/边界；只读对应案例 | 先说清要解决的论证问题，再修改；不自动扩成全文 |

| 引文/批注返修/版本比较 | 证据契约、本项目来源与变更记录，再按受影响部分补读规范 | 不跨项目带入数字，批注修订有来源并保留未解决项 |

章节案例按“问题—证据—解释—边界”寻找，不以句子华丽或与目标期刊同名作为唯一选择依据。参考论文只迁移论证组织、视觉编码和表达方法；不迁移其样本数、性能、实验划分、传感器条件或结论。

框图和示意图不只是数据图的配色变体。按当前方法语义选择真实参考案例，核对原论文版本、图号/页码和实际图页，逐项看模块形状、分组、层级、连接端点、箭头含义、训练/推断边界、标签、图标及留白。把可迁移的元素规则落实到可编辑 PPTX/SVG/TikZ 源；仅看过文字或缩略信息时不得声称已完成元素级视觉审查，也不得把重建图误称原作者源文件。

对 GitHub 专业绘图库、Skill 或 MCP 资源，先查规范库的资源登记及适用条件，核验作者/仓库、版本或 commit、许可证、维护状态和当前可用工具。资源被列入规范库只代表参考或候选，并不自动授权安装、执行、联网下载大文件、替换当前连接或升级本地工具链。按用户任务和现有授权调用；无法确认来源/兼容性时保留待核，不以工具名冒充已有能力。

## 图件制作闭环：最小执行判据

图件任务沿快速路由选所需图表或组件规范，再按产物执行下列相关检查；纯数据图不为凑流程额外加载整份组件案例。方法总览使用其独立路由；旧场景示意的“场景→机制→输出”“三块以内”不能强加给方法总览。契约中的尺寸、字号目标和渲染器偏好有任务范围，不自动推广成所有期刊硬要求；工具选择仍遵当前宿主技能和已授权能力，不强制新增库或指定某一生成库。

1. **四门分开回执**：事实门核科学路径、主张/箭头/输出与来源及实测/合成/方案状态；工程门核可编辑性、源文件打开/真实渲染/独立重建；版式门核最终尺寸下字、图、连接及裁切；表达门按图型核科学问题与信息组织是否清晰；方法总览重点核输入—表征—核心模块—输出及训练/部署边界。各报通过/失败/未核及证据，不用“工程通过”替代科学或表达通过。
2. **原生对象有实据**：要求原生 PPT 时，主模块、标签和连接线须可独立编辑，检查对象类型和关键语义；整张 PNG/SVG 插入 PPT 不算原生可编辑主图。数据/波形面板可按契约用矢量插图，但逐项标识，不能用大量无意义对象提高“原生比例”。
3. **渲染必须来自交付源**：从实际生成的 PPTX 经可用渲染器导出 PDF/PNG并打开检查，记录渲染器/版本与输出对应关系；另画一张 PNG 不能证明 PPTX 排版。某渲染器通过不等于其他宿主已核。
4. **最终嵌入状态也要检查**：统计原生文本之外，还须检查插入的 SVG/波形/坐标/图例经组合与插入缩放后的有效字号、纵横缩放和长宽比。按最终物理尺寸核查，不以原始字体值或放大屏幕截图放行。小于本次约定阈值的文字逐项报位置/数量/原因；不能通过压扁面板、改变波形比例或缩字解决拥挤，应重排或重生成。自动筛查与真实渲染目视均保留。
5. **源可移植并实测重建**：源码使用输出参数或脚本相对路径，附真实依赖与命令；在新进程、另一输出目录重建关键文件，避免会话专属硬编码路径。静态语法检查不算重建通过；短单元分阶段保存，截断或语法失败先修该单元。
6. **阶段性交付，不无限改稿**：首版渲染后修已发现的关键问题并再次渲染，按用户任务及时交付当前源文件、PPTX/目标格式、对应真实预览和分门简短 QA（方法总览另附盲读结果或未完成状态）。缺陷未闭合可交候选并明确列出；失败、未审或仅自查产物不得登记为获批范图。不得由文档更新推断本轮作品合格。

## 方法总览：先语义后排版

方法总览服务方法章节导航，复杂度由真实方法决定，不用“三个空框”或全部网络层堆砌替代解释。先从当前授权稿件/公式/源码建立节点与边清单，记录文件及节/行和已实现/计划/待核状态：输入及可用时机，必要表征/维度，核心模块真实变换，边传递的对象及数据/参数/监督/反馈类型，训练与部署差别，输出粒度/单位/发布时机。未知维度、机制、贡献或能力不得补造；作者主张的贡献标记映射正文和验证，不自动宣布创新。

根据真实依赖选单主链、多分支融合、训练/部署泳道或总览加局部放大；concat、sum、选择/门控等操作不能混画。每条边均解释源、目标和对象，回边注明时间/迭代条件。另让独立审阅者仅据图回答输入、核心机制、输出、训练部署差别、贡献位置，并与来源清单对照；没有独立审阅只报未做，不能自称盲读通过。

## 文件级验收：执行成功与交付正确分开

以当前锁定规范中的组件指南工程补丁为依据；确需追溯旧反例和工具日志时才读[历史链接](historical-drive-links.md)，不以其替代正式规范。资料存在不等于检查器已在当前产物运行，不自动授权安装、执行或改变平台指定的生成工具链。

- **箭头落盘与方向**：代码属性赋值成功不证明序列化成功。已记录反例限 python-pptx 1.0.2 的 LineFormat 动态赋 `end_arrowhead=True`，不能泛化全部版本。检查交付 PPTX 的 OOXML `headEnd/tailEnd`、连接端点、翻转/旋转及真实渲染方向，按节点—边契约复核；独立三角形另查。直接箭头数为零不证明图无可见箭头，非零也不证明方向/连接正确，不批量盲补同向箭头。
- **三类保真分开**：云端记录与下载字节匹配是传输保真；包内 manifest 与实际各工件匹配是清单一致；PDF/PNG确由该源文件渲染是来源链证据。三者分别报，不因同包存在或哈希一致就宣称真实渲染。失配保留原件/实测值和未知原因，不静默改清单掩盖失败，也不直接指控篡改。
- **审计与重建分开**：静态扫描 exit 0 只表明扫描完成，不证明字体、组变换、图片内字号、连接语义或视觉通过；AST/语法通过也不等于运行安全批准。另目录重建和渲染保存命令、版本、日志、退出码、工件与哈希，再做实际图像/方法语义核验。不得覆盖原件或以修复版替换已冻结比较的 prompt、评分或产物；新规则仅用于后续生产和明确标识的修订版。

## 冲突、版本与缺失材料

- 科研事实是独立约束：已核实验数据、冻结结果与来源口径不能被模板、风格建议、参考文章或作者措辞偏好覆盖。发现事实冲突先标出，不挑更好看的数字。
- 格式优先级：适用于当前文章类型/阶段的最新已核官方硬要求 → 不违反硬要求的本项目已确认风格 → 通用团队默认 → 案例观察。官方建议与硬要求分别标记，不把默认字号/配色/线宽写成期刊强制项。
- 项目风格与用户新要求冲突时，采用用户明确的新指示更新候选风格；不得因此违背科研事实或隐瞒官方硬要求冲突。确需用户决策时说明具体冲突。
- 日期新不等于已验收。区分 `current/approved`、`candidate`、`historical`、`pending verification`；以入口和实际文件状态核对。Inbox、样稿、代码压缩包或重建 PPTX 不自动升级为官方模板或通用标准。
- 已有模板链接 ≠ 已下载模板；已下载 ≠ 构建可用；构建通过 ≠ 视觉通过。记录官方来源、版本/获取日、适用期刊与阶段、实际资产 ID 和验证状态。
- 对页数、匿名化、图件规格、AI 披露等时效性要求，核对当前官方来源。页数上限、建议长度与超页收费起点不能混写；如受限无法核验，保留“待核”，不从其他期刊填补。
- 只有 PDF/文本或元数据时明确阅读层级。文件无法取正文时不得判为空文件；优先用必要文本和证据提取核对；Chat 视觉读取经已核 Drive PDF 或页预览 ID，失败则报告具体缺口。附件请求按[文件交付策略](file-delivery-policy.md)处理。
- 缺少本项目 profile 时先按已读通用和官方要求形成**候选项目规则**，标明待作者确认；不能借用别的项目 profile 冒充。缺少不可推断的关键事实时暂停依赖它的结论，继续独立可做部分。

## 执行落点与交付核验

每次关键写作或制图前，给出简短“本轮采用规则”：项目/任务、实际已读规范名称及版本或修改日期、适用期刊/阶段、需要处理的冲突/待核项。不要用这份清单替代用户要求的实际成果。

将适用规则落实到本轮 TeX、图源或项目候选 profile；正式版本的 `style_snapshot` 至少记录 Drive 文件 ID/修订或修改日期、期刊官方 URL 与核验日、已用模板资产身份、项目风格版本、未确认项，以及相关图表默认参数的来源。Skill 的链接存在不代表该规则已在作品中执行。

质量验收同时检查：科学问题和结论有证据支持、基线条件可比、统计单位与不确定性含义明确、图表支持最小充分结论，以及实际渲染可读。没有实际页面/图像就把视觉状态保留为未核。

## Drive 连接与权限边界

ChatGPT 可通过已连接 Drive 获取规范和已发布审阅文件，但不能把自己的 OAuth 权限转授本机 WebCodex。本地发布器使用独立授权或用户批准的同步方式；不在聊天索要 token。

只学习参考图中可迁移的结构，不默认允许复制原图或公开传播原文。保持现有私人权限，未经用户明确要求不公开共享论文或规范。
