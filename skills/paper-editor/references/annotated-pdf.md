# 带批注 PDF 的 SCI 论文返修流程

本文中的 Drive 路线适用于已配置且选择该渠道的项目。无 Drive 的项目可继续本地工作，并按[文件交付策略](file-delivery-policy.md)使用实际可用且获准的 MCP 文件接收。`drive_links_only` 只在连接明确返回该设置时生效。

## 输入与版本定位

项目使用 Drive 批注时，先按已核文件 ID 和展示或发布回执，由项目连接原生 `paper_review_comments` 读取评论及回复；PDF 内嵌批注通过 Runner 的 PDF 工具解析；Chat 需要视觉定位时，通过 Drive 连接器按该 PDF 或已核页预览 ID 查看。处理意见和修改 TeX/图源沿用原生编辑及构建。附件请求按[文件交付策略](file-delivery-policy.md)处理。

用户可能上传已下载、带修改意见的 PDF、单页截图、手写批注、审稿意见 Word/Markdown。先从当前 Chat 的实际附件获取文件；若要本地修改必须通过已授权 MCP 的文件导入/版本管理工具传入，而不是假设本地已出现同名文件。

1. 用 PDF 本身/metadata/封面/manifest 匹配原稿版本；核对 SHA256（带批注 PDF 字节会变化，不能以原始 PDF hash 与批注后的文件必须相等判断）。如果版本不明确，依页面内容及稿件编号核对。
2. 对真实 PDF annotations 提取页码、坐标、标注类型、内容、作者注释及对象信息；对扁平化高亮、涂鸦、手写文字，用页面图像实际检查。不要把正文标黄都假设有完整文字建议。
3. 在当前对话或已有批注表中记录稿件身份、页码、批注内容、坐标、对应 TeX 或图源、解释可信度和处理状态。需要长期逐项审批时再使用审阅 issue 或结构化提案。
4. 通过 TeX 源映射/标签/图号定位修改目标；不通过“PDF 第 7 页”直接修改全局第 7 页源代码，必要时查构建映射和上下文。
5. 针对模糊或相互冲突的批注标注未解决，合理继续处理其他明确问题，不私自改变科研结论。
6. 依照[修订展示与批注确认](review-confirmation.md)在当前版本上展示候选改动并记录逐项意见。用户确认后按本轮保存修订的要求写入 TeX 或图源，构建 PDF 并按页核验。提交 `ANNOTATION_RESOLUTION.md` 或等价表记录 resolved/partially-resolved/needs-author/blocked。
7. 按本次选定范围交付。需要 Drive 展示时只交已选文件，有明确正式发布指令时再登记正式版（用户要求全文则 PDF，单图则图预览）。

## 限制

没有访问到 PDF 页面图像时不能声称已经读懂图上的手绘箭头；无法解析的批注应明确报告。优先内置 PDF 注释解析与视觉能力，OCR 仅在无更可靠方法时考虑。不得通过直接涂改批注后的 PDF 取代论文源文件修订。
